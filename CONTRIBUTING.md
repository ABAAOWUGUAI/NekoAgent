# Contributing

Open an issue before a large feature or a new runtime integration. Keep pull
requests focused and include the relevant unit, integration or scenario tests.

Never submit real tokens, `.env` files, SQLite databases, screenshots of
private conversations, QQ identifiers, production manifests or copied model
responses containing personal data. Use synthetic fixtures.

For capability changes, document the required Capability, approval behavior,
network policy and Delivery/ACK effect. A model prompt is not an authorization
mechanism.
